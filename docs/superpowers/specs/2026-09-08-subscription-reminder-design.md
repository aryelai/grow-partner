# 微信订阅消息与自动提醒设计

## 状态

- 设计日期：2026-09-08
- 设计结论：已由用户逐段确认
- 实施范围：先完成通知订阅消息与自动提醒；作业、计划、习惯提醒和其他 PRD 扩展能力不在本轮实现

## 背景

当前通知数据已经包含事项时间、提前量、提醒对象和 `isReminded`，但 `reminder` 云函数仍为占位实现，前端也没有调用 `wx.requestSubscribeMessage`。基础版需要在微信一次性订阅消息的约束下，为家庭成员提供可审计、防重复、可降级的自动提醒。

当前使用免费云开发环境，每月资源额度为 3000 点。调度频率必须兼顾提醒及时性和空轮询成本。

## 目标

- 用户可以通过明确的点击操作，为自己增加一次“待办事项提醒”授权。
- 通知只能选择一个提前时间：提前 1 天或提前 2 小时，默认提前 2 小时。
- 系统按照通知时间和提醒对象，自动向已授权的家庭成员发送一次订阅消息。
- 定时触发重复执行时，同一通知版本不会向同一接收人重复发送。
- 未授权、拒绝、接口错误、敏感内容和通知过期均有明确状态，不静默失败。
- 消息点击后进入对应通知的只读详情页。
- 默认调度频率适配免费云开发环境，并保留付费后提高频率的路径。

## 非目标

- 本轮不发送“日程提醒”模板，不实现习惯打卡提醒。
- 本轮不为作业和计划增加自动提醒。
- 本轮不接入订阅消息服务端事件回调。
- 本轮不实现提醒统计后台、运营报表或复杂优先级队列。
- 本轮不研讨或实现其他 PRD 扩展能力。
- 不申请更多订阅消息模板，不尝试绕过微信的一次性订阅限制。

## 平台约束

- `wx.requestSubscribeMessage` 必须由用户点击行为触发，创建者不能代替其他家庭成员授权。
- 一次性订阅模板每成功发送一条消息消耗一次有效授权；两个提前时间需要两次授权，因此基础版限制为单个提前时间。
- 微信没有向小程序开放可靠的剩余授权次数查询接口，系统只能显示本地估算值，发送结果以微信接口为准。
- 定时触发器可能重复执行，发送流程必须具备应用级幂等。
- 微信发送接口不提供业务幂等键。调用成功后、状态落库前发生进程中断时，无法同时保证绝不重复和绝不丢失；本项目优先避免重复发送。
- 已选模板的时间字段是 `time` 类型，只承载 `HH:mm`；日期放入事项描述字段。

## 方案选择

采用“定时扫描到期通知 + 按接收人生成发送记录 + 用户授权次数池”。

未采用的方案：

- 保存通知时预生成所有接收人任务：通知时间、提醒对象和家庭成员关系变化时需要持续同步任务，复杂度较高。
- 到期后直接发送：缺少可靠的防重、重试和审计能力，不满足生产可用要求。

## 前端交互

### 通知编辑页

- “提前 1 天”和“提前 2 小时”由多选改为单选，默认提前 2 小时。
- 新建通知时从家庭设置读取默认提前量和提醒对象；默认提前量即使存在历史多值，也只取第一个有效值。
- 开启提醒时必须至少选择一个家庭关系作为提醒对象。
- 页面明确展示提醒对象，避免使用不可见的默认值。
- 当前用户属于提醒对象且预计授权次数不足时，主按钮显示“保存并订阅提醒”。点击后先请求一次模板授权，再登记结果并保存通知。
- 用户拒绝或关闭订阅弹窗时仍保存通知，并提示“通知已保存，微信提醒未授权”。
- 当前用户不属于提醒对象时只保存通知，不弹出订阅授权。
- 修改已经完成调度的通知时间、提前量或提醒对象时，页面提示这会创建新的提醒版本，并可能再次通知所选成员。

### 设置页

- 家庭默认提前量同步改为单选，只允许提前 1 天或提前 2 小时。
- 增加“微信提醒”状态卡片，展示功能状态、预计可用次数和下一条待提醒事项数量。
- 按钮文案为“增加 1 次提醒”。每次点击只请求“待办事项提醒”模板一次。
- 页面使用“预计可用次数”，不得描述为永久授权或保证送达。
- `accept` 增加预计次数；`reject`、`ban`、`filter` 分别显示可理解的提示，不增加次数。

### 通知详情页

- 新增只读详情页，展示标题、来源、分类、正文、图片、事项时间、提前时间和提醒对象。
- 所有家庭成员均可查看同家庭通知；只有具有通知维护权限的用户显示编辑入口。
- 订阅消息统一跳转到该页面，不直接进入编辑页。

## 云函数职责

### `notice`

- 校验开启提醒时 `remindAdvance` 只能包含 `120` 或 `1440` 中的一个值。
- 根据 `remindTime - remindAdvance` 计算 `scheduledAt`。
- 新建提醒时生成 `reminderVersion = 1` 和 `reminderState = "scheduled"`。
- 修改提醒时间、提前量、提醒对象或启停状态时递增 `reminderVersion`；仅修改标题或正文不创建新提醒版本。
- 删除通知后，旧发送记录由调度器在下次处理时标记为 `canceled`，不级联删除审计记录。
- 不再使用 `isReminded` 作为调度查询条件。仅当当前版本所有目标接收人都成功发送时设为 `true`，否则保持 `false`。

### `reminder`

提供以下 action：

- `getStatus`：要求有效用户身份，返回功能状态、待办模板 ID、当前用户预计可用次数和待提醒数量；不返回 OpenID。
- `recordSubscription`：只记录当前 OpenID 的授权结果；校验模板 ID、结果枚举、请求编号、每日登记次数和预计次数上限。
- `run`：只允许 `cloud.getWXContext().SOURCE === "wx_trigger"`，客户端调用一律拒绝。定时触发调用不要求事件中携带 `action`，通过可信来源直接进入调度流程。

`run` 分为两个阶段：

1. 查询 `reminderState = "scheduled"` 且 `scheduledAt <= now` 的通知，按当前家庭成员和 `remindTargets` 为每个接收人生成确定性发送记录，然后将通知标记为已物化。
2. 查询已经到期的等待或重试记录，确认通知仍存在、版本一致、提醒仍启用、接收人仍属于同一家庭且关系仍匹配，再尝试占用一次预计授权并发送。

单次运行限制批次数和处理数量，未处理完的记录留给下一次触发，避免云函数超时和意外消耗免费资源。

## 数据模型

### `notices` 新增或收紧字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `remindAdvance` | `number[]` | 保持与现有结构兼容，但最多且必须只有一个有效值 |
| `scheduledAt` | `Date \| null` | 实际应开始发送的时间 |
| `reminderVersion` | `number` | 提醒配置版本，从 1 开始 |
| `reminderState` | `string` | `disabled`、`scheduled`、`materialized` 或 `completed` |
| `isReminded` | `boolean` | 当前版本所有目标均发送成功时为 `true`，不参与调度查询 |

历史通知缺少新字段时，在读取和更新边界做兼容；只有再次保存并开启提醒后才进入新调度流程，不对历史数据执行批量迁移或补发。

### `message_subscriptions`

客户端禁止直接读写。文档 ID 由服务端对 `openid + templateId` 做 SHA-256 得到，避免客户端控制主键。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `_id` | `string` | 确定性哈希 |
| `openid` | `string` | 接收人 OpenID，仅云函数可见 |
| `templateId` | `string` | 模板 ID |
| `estimatedAvailableCount` | `number` | 本地预计可用次数，范围 0 至 50 |
| `lastDecision` | `string` | `accept`、`reject`、`ban` 或 `filter` |
| `recentRequestIds` | `string[]` | 最近 20 个请求编号，用于防止重复登记 |
| `dailyRecordDate` | `string` | 北京时间日期 |
| `dailyRecordCount` | `number` | 当日登记次数，最多 20 次 |
| `createdAt` | `Date` | 创建时间 |
| `updatedAt` | `Date` | 更新时间 |

授权结果来自客户端，因此预计次数只能作为调度优化，不能作为微信已授权的安全证明。微信发送接口是最终授权边界。

### `reminder_deliveries`

客户端禁止直接读写。文档 ID 由服务端对 `noticeId + reminderVersion + recipientOpenid + templateId` 做 SHA-256 得到。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `_id` | `string` | 确定性幂等键 |
| `noticeId` | `string` | 通知 ID |
| `familyId` | `string` | 家庭数据边界 |
| `reminderVersion` | `number` | 对应通知提醒版本 |
| `recipientOpenid` | `string` | 接收人 OpenID，仅云函数可见 |
| `recipientRelation` | `string` | 物化时的家庭关系 |
| `templateId` | `string` | 待办事项模板 ID |
| `scheduledAt` | `Date` | 预计开始发送时间 |
| `deadlineAt` | `Date` | 通知事项时间，超过后不再发送 |
| `status` | `string` | `waiting_subscription`、`sending`、`retry`、`sent`、`failed`、`uncertain`、`expired` 或 `canceled` |
| `attemptCount` | `number` | 已发起的发送次数 |
| `nextAttemptAt` | `Date` | 下次允许尝试的时间 |
| `lockExpiresAt` | `Date \| null` | 发送占用锁的失效时间 |
| `lastErrorCode` | `number \| null` | 微信错误码，不记录敏感载荷 |
| `lastErrorMessage` | `string` | 截断并清理后的排障信息 |
| `sentAt` | `Date \| null` | 成功发送时间 |
| `createdAt` | `Date` | 创建时间 |
| `updatedAt` | `Date` | 更新时间 |

## 幂等、并发与授权占用

- 物化发送记录时使用确定性 `_id`，重复创建视为同一任务，不生成第二条消息。
- 占用预计授权次数和将发送记录改为“发送中”必须在数据库事务中完成。
- 同一接收人的消息在一次函数运行中串行发送，降低微信 `43108` 并发错误概率。
- 明确收到微信失败响应时，根据错误分类恢复预计授权或等待重新订阅。
- 如果请求可能已经到达微信、但云函数没有拿到明确响应，发送记录进入“状态不确定”，不自动重试，以避免重复提醒。
- `sending` 状态超过锁定时间但没有明确结果时同样转为“状态不确定”，不再次发送。

## 错误处理

| 场景 | 行为 |
| --- | --- |
| `43101` 用户未订阅或次数耗尽 | 将预计次数归零，记录恢复为等待订阅；在事项到期前可因新授权再次发送 |
| `43107` 能力或模板被封禁 | 标记系统阻断，不自动重试，并通过 `getStatus` 暴露配置异常 |
| `43108` 同一用户并发发送 | 恢复预计次数，延后至下次调度重试 |
| `47003` 模板参数错误 | 标记配置错误，不消耗预计次数，不重复发送 |
| `45168` 命中敏感词 | 使用固定安全标题和固定安全描述重试一次；仍失败则终止 |
| 明确的临时服务错误 | 恢复预计次数，在截止时间前最多重试 3 次 |
| 网络中断且结果未知 | 标记状态不确定，不自动重试 |
| 通知删除、版本变化、成员离开或关系不再匹配 | 标记已取消，不发送 |
| 当前时间达到或超过事项时间 | 标记已过期，不发送迟到消息 |

日志仅包含 action、通知 ID、发送记录 ID、错误码和截断错误摘要，不记录订阅消息正文、家庭邀请码、完整 OpenID 或其他敏感载荷。

## 配置与权限

- 模板 ID与 AppID绑定但不是密钥，可以作为云函数受控常量保存，并由 `getStatus` 返回前端。
- `MINIPROGRAM_STATE` 仅允许 `developer`、`trial`、`formal`。当前环境配置为 `developer`；缺失或非法时禁止发送并报告配置错误。
- 不读取、不保存、不要求用户提供 AppSecret。
- `message_subscriptions` 和 `reminder_deliveries` 的客户端数据库权限均设置为拒绝。
- `recordSubscription` 只能影响当前 OpenID，不能接受客户端传入的 OpenID、家庭 ID或预计次数。
- `run` 只接受微信定时触发来源；不提供客户端可调用的测试发送后门。

## 索引

需要在云开发控制台创建：

```text
notices:               reminderState ASC, scheduledAt ASC
reminder_deliveries:  status ASC, nextAttemptAt ASC
reminder_deliveries:  noticeId ASC, reminderVersion ASC
```

`message_subscriptions` 使用确定性文档 ID读取，不需要额外唯一索引。

## 调度频率与免费额度

- 定时触发器每 30 分钟执行一次，使用北京时间时区。
- 每 30 分钟约产生每月 1440 次定时调用；相比每 5 分钟约 8640 次，更适合当前 3000 点/月的免费体验环境。
- 提前 2 小时提醒的实际发送时间最多可能晚约 30 分钟；提前 1 天提醒同理。
- 上线后观察资源点消耗。如果资源消耗仍偏高，先降为每小时一次；如果业务明确需要 5 分钟级精度，再评估升级付费套餐。
- 每次空轮询只执行必要的索引查询，不扫描完整集合。

## 云环境部署

1. 创建 `message_subscriptions` 和 `reminder_deliveries` 集合，客户端权限设为拒绝。
2. 为 `notices` 和 `reminder_deliveries` 创建约定索引。
3. 将当前云环境的 `MINIPROGRAM_STATE` 配置为 `developer`。
4. 部署 `notice` 和 `reminder` 云函数，并为 `reminder` 部署 30 分钟定时触发器。
5. 在微信开发者工具中重新编译并确认问题面板没有新增错误。
6. 使用真机完成订阅和消息接收验收；开发者工具只能验证页面和调用流程，不能替代真实微信送达结果。

## 真机验收标准

- 用户点击“增加 1 次提醒”后接受授权，预计次数增加 1。
- 创建一条当前用户属于提醒对象的测试通知，调度时间落在下一次触发范围内。
- 目标用户在 30 分钟调度窗口内只收到一条消息。
- 消息字段与模板匹配，日期、时间、类型和状态可理解。
- 点击消息进入正确通知的只读详情页。
- 拒绝授权时通知仍可保存，但页面明确提示微信提醒未授权。
- 未授权的其他家庭成员不会收到消息，也不会消耗当前用户的预计次数。
- 重复触发、重复物化和已发送任务不会产生第二条消息。
- 通知过期、删除、禁用或接收人离开家庭后不会发送。

## 发布观察与回退

- 部署后记录触发次数、扫描数量、发送成功数、等待订阅数和错误码分布，但不记录消息正文和完整 OpenID。
- 免费资源点异常增长时，先将触发频率降为每小时一次。
- 出现模板配置或误发风险时，先停用定时触发器；保留发送记录和订阅状态用于排障，不删除审计数据。
- 待通知提醒完成真机验收后，再按项目剩余开发清单继续推进；所有基础功能完成后再与用户研讨 PRD 扩展能力。
