# 确认版布局原生实施计划

## 目标与边界

将用户已认可的 `designs/home-layout-redesign/layout-v3.html` 落实为原生 WXML/WXSS 和真实业务交互。底部导航为首页、作业、通知、成长、我的；首页完整展示当天课程，以上午四节、下午四节为常见布局，不截断实际多余课程。

本轮允许本地实现和验证；不提交、推送、部署、上传、发布，不修改密钥、云环境或生产历史数据。保留所有已有工作区修改，尤其是通知 AI 导入及课程表开发代码。项目治理配置中阶段和发布规则仍沿用已声明事实，不自行更新 devres。

## 现状与调研决策

- 原生五栏导航和首页已存在，但第四栏仍为习惯，计划是独立非 Tab 页面。
- 作业已有科目、日期、完成接口，可复用；通知只有提醒状态，没有事项完成状态。
- 课程表、习惯、计划、通知均通过已有云函数访问，游客只用本地示例。
- 采用组合复用：保留微信原生 TabBar、原生按钮和输入控件；抽出计划控制逻辑供独立页与成长内的原生组件复用。无需新增 UI 框架或第三方依赖。
- 已检查仓库、现有 SDK、技能及微信组件生命周期/WXSS官方文档地址。文档网站当前无法读取，不能据此宣称外部规范核验通过；以现有能力、自动化测试和开发者工具编译为进一步证据。

## 架构与文件

- `miniprogram/app.json`、`app.wxss`：成长栏命名及公共色彩、顶部操作和完成反馈样式；使用系统导航栏，不重复补偿顶部安全区。
- `utils/home.js`、`pages/home/*`：北京时间课程分组、全天列表、正确数量和导航；完整主题、紧凑课表及稳定成长卡片。
- `pages/homework-list/*`：值标签、大字号、顶部固定 AI/新增/更多、直接完成和撤销；复用 `homework.toggleCompleted`。
- `utils/notice.js`、`pages/notice-list/*`、`pages/notice-detail/*`、`pages/notice-edit/*`：通知状态、组合筛选、关键时间、完成和恢复；新增事项/截止时间为可选值。
- `cloudfunctions/notice/index.js`：旧通知默认待处理，新增通知默认未完成；事务内按明确目标状态设置完成，校验家庭及成人角色；提醒字段完全独立。
- `utils/plan-controller.js`、`components/plan-panel/*`、`pages/plan-list/*`：复用真实计划、日周月导航及任务勾选，防重复提交和陈旧请求覆盖。
- `pages/habit-list/*`：成长同级页签、可见新增、习惯目标表单、打卡详情入口；复用已有习惯接口和积分规则。
- `utils/guest-experience.js`：本地演示完成状态，不发起业务写入；真实会话切换后清除演示覆盖。
- `tests/*`、`scripts/validate-project.js`：行为、权限、兼容性、组件依赖和关键样式检查。
- `cloudfunctions/README.md`：新增可选字段、状态语义及后续部署依赖，不冒充已部署。

## 顺序与验收证据

1. 测试先行：全天课程、上午下午分组、旧通知默认待处理、严格布尔目标状态、跨家庭与孩子拒绝、提醒不受完成影响、游客完成/恢复、连续点击和筛选一致性。
2. 实现首页全天课程及公共样式，保留真实课程数量，缺时间不编造时间。
3. 实现作业固定顶部操作和完成撤销，完成后重载当前筛选；未完成页即时消失，已完成页可恢复。
4. 实现通知云函数完成接口和时间兼容字段，再接列表/详情/编辑；组合筛选在服务端分页前执行，不只过滤当前页；失败保留原状态。
5. 实现成长页签，计划复用组件和明确的新习惯表单；首页今日计划始终进入当天日计划，而非上次浏览的周/月周期。
6. 运行 `node --test tests/*.test.js`、`node scripts/validate-project.js`、`git diff --check`；读取完整退出状态。
7. 用项目声明的微信开发者工具命令打开项目并检查模拟器编译和关键页面。至少覆盖窄屏、主流、大屏；设备或登录无法获取时记录缺口，不以 HTML 浏览器检查替代原生模拟器/真机。

## 风险与回滚

- 不批量迁移旧通知。缺少 `isCompleted` 的记录按未完成读取；新接口使用 `isCompleted === true`，不从 `isReminded` 推断。完成不取消或重新触发提醒，用户仍可单独编辑提醒。
- 孩子账号继续只读通知，不扩大原有通知维护权限；作业、习惯、计划的既有执行权限保留。
- 可选事项/截止时间：旧调用不提供字段时，更新必须保留原值；明确空值才清空，不允许畸形日期。
- 新通知接口必须在后续部署 notice 云函数后才能在真实环境使用；本轮仅开发，不宣称云端可用。
- 回滚按本轮差异精确恢复，不硬重置或覆盖已有脏工作区；旧客户端继续使用原接口，新增字段可保留，不删除生产数据。
- 真机、键盘、安全区、弱网和字体放大仍需 iOS/Android 实测，自动化通过不等于真机通过。

## 确认点

用户已授权开始原生开发，不需要再确认视觉方向。部署、提交推送、上传和发布在本轮之外，需另行明确指令。
