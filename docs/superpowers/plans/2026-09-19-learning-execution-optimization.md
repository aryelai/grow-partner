# 家庭学习执行闭环优化实施计划

## 目标

把现有“信息登记工具”完善为可验证的家庭学习执行闭环：重要任务不遗漏、孩子能自主反馈、家长只处理异常、识别结果可对照核验，并保持旧数据无迁移可用。

## 当前范围

### 第一阶段：执行闭环

1. 逾期作业优先展示，首页进入全部待完成作业，作业页支持“指定日期/全部待办”切换。
2. 作业增加可选学习状态：需要帮助、待家长检查、待订正、已订正；原有完成状态保持兼容。
3. 通知增加内部要求清单，支持逐项完成；待处理通知按逾期、临近截止、无时间排序。
4. 作业、通知、课程表识别后保留本地原图，支持放大对照，离开页面后仍按既有流程清理临时云文件。
5. 孩子可创建和维护自己创建且由自己执行的计划，不能修改或删除成人计划。

### 第二阶段：减少重复管理

1. 今日清单聚合作业、通知要求、习惯和个人计划，不复制业务数据。
2. 课程表增加日期级临时调课，不改写固定周课表。
3. 家庭识别词库保存校内简称与常用表达，只作为识别上下文，不自动改写结果。
4. 每周复盘使用客观完成、逾期、订正和求助数据，不做排名或推测性评价。
5. 数据管理增加可审计的导出、退出家庭和删除说明；破坏性操作单独确认并留回滚边界。

## 非目标

- 不开发教师端、成绩排名、家校聊天、姿态照片分析或诊断。
- 不让识别结果未经核对直接写入业务数据。
- 不修改生产数据，不在本地实施阶段部署、上传或发布。
- 不强制所有作业经过多阶段流程；学习状态始终可选。

## 架构与兼容策略

- 作业沿用 `isCompleted`，新增可选 `learningState`，旧记录缺失时按普通状态处理。
- 通知沿用 `isCompleted`，新增 `requirements` 数组；旧通知缺失时继续使用整条完成按钮。
- 今日清单只聚合各业务集合，不创建重复记录；完成动作仍写回原业务集合。
- 临时课程采用独立日期覆盖层，固定课程表仍按星期读取。
- 新权限在客户端和云函数双重校验；孩子计划以服务端 `createdBy` 与 `assignee` 共同约束。

## 任务顺序与完成证据

1. 先补失败测试：排序、旧数据默认值、权限、逐项完成、原图保留和页面入口。
2. 修改云函数校验、公开字段和原子更新行为。
3. 修改公共工具和页面控制器，避免在 WXML 中复制业务判断。
4. 按移动端设计基线实现状态标签、清单行、按钮热区和安全区。
5. 运行 `node --test tests/*.test.js`、`node scripts/validate-project.js`、`git diff --check`。
6. 第一阶段完成后再进入第二阶段；每个阶段都保留独立可回退提交边界。

## 风险与回滚

- 新字段必须是可选字段，禁止依赖一次性数据库迁移；回滚旧代码后旧字段可安全忽略。
- 通知清单和孩子计划必须使用服务端事务或所有权复核，避免并发覆盖和越权。
- 全部待办查询最多扫描受控候选集并返回截断标记，公开扩量前再评估索引与分页。
- 临时原图只保留在当前页面本地状态，不转存为业务附件。
- 发布、部署和真实数据删除不属于本计划的自动授权范围，需在对应阶段单独确认。
